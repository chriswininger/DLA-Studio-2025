# 3D DLA Simulation

A 3D extension of the 2D Diffusion-Limited Aggregation simulation, rendered with Three.js via `@react-three/fiber`.

## Overview

Walkers are spawned as spheres within a configurable bounding sphere and perform a random walk in 3D space. When a walker drifts within the configured stick distance of any cluster point, it becomes part of the cluster. A line is drawn between each newly stuck particle and the cluster node it attached to, producing a branching tree structure.

By default the simulation seeds a single stuck point at the origin ("Center Sticky") and confines all walkers within a bounding box (default half-extent of 8 units). Optionally, the floor of the bounding box can also act as a sticky surface ("Floor Sticky"), causing walkers that reach the bottom to stick in place and form independent root points for new growth.

## Controls

- **Particles to Spawn** -- number of walkers to create on each spawn action
- **Spawn Sphere Radius** -- radius of the sphere within which new walkers are randomly placed
- **Stick Distance** -- how close a walker must be to an existing cluster point to stick (larger values produce denser, bushier structures; smaller values produce thinner branches)
- **Center Sticky** -- when checked, a seed point exists at the origin; unchecking removes it. Can be combined with Floor Sticky or used alone
- **Floor Sticky** -- when checked, walkers that reach the floor of the bounding box (`y = -boundHalfExtent`) become stuck, each forming its own root node. Growth then branches upward from the floor
- **Start / Stop** -- run or pause the random walk simulation
- **Reset** -- clear all walkers and cluster, restore all controls to defaults

The 3D viewport supports orbit controls (click-drag to rotate, scroll to zoom).

## Architecture

- **`dla-3d.ts`** -- simulation engine: `createDLA3DState`, `stepDLA3D`, types (`Point3D`, `ClusterEntry3D`, `ClusterMap3D`, `DLA3DState`)
- **`three-dimensional-dla-slice.ts`** -- Redux state for UI controls and persisted simulation data
- **`three-dimensional-dla.tsx`** -- main page component with the Three.js canvas and simulation loop
- **`sphere-spawn-controls/`** -- spawn parameter inputs (particle count, radius)
- **`simulation-controls/`** -- simulation parameter inputs (stick distance, center sticky, floor sticky)
- **`three-dimensional-dla-constants.ts`** -- defaults and buffer limits

## Performance

Rendering uses `InstancedMesh` for both walkers and cluster spheres, and a pre-allocated `BufferGeometry` for connection lines. All position and color updates happen imperatively inside `useFrame` with no React state changes during simulation, matching the approach used by the 2D canvas renderer.

## Blender Export

The **Export to Blender** button downloads a Python script (`dla_paths.py`) that recreates the DLA cluster as NURBS
curve paths inside Blender. The DLA tree is decomposed into unbranched path segments — each segment becomes a separate
spline within a single Curve object.

### How to use the exported script

1. Run the DLA simulation until you have a cluster you like.
2. Click **Export to Blender** to download `dla_paths.py`.
3. Open Blender.
4. Switch to the **Scripting** workspace (top menu bar).
5. Click **Open** in the text editor and select the downloaded `dla_paths.py`.
6. Click **Run Script** (or press Alt+P).

The script creates a Curve object called "DLA_Paths" in the active collection. From there you can apply modifiers (e.g. a Bevel for thickness), convert to mesh, or use it as a basis for geometry nodes.

### Why a Python script instead of a .blend file

The `.blend` format is a raw memory dump of Blender's internal C structs with an embedded schema (SDNA) that changes
between versions. Writing valid `.blend` files outside of Blender would require serializing hundreds of interdependent
structs with exact memory layout — no library exists for this in any language. Generating a `bpy` Python script is the
canonical approach used by Blender's own import/export add-ons.

### Architecture

- **`blender-export/blender-export.ts`** -- `extractPaths` decomposes the cluster trees into linear segments;
  generateBlenderScript` produces the Python source
- **`blender-export/blender-export.tsx`** -- export button component, triggers a file download
